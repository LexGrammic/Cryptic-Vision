# Purpose

This guide introduces the Pocket Runtime Doctor interface and explains the standard workflow for observing, analyzing, and reporting on software systems.

Pocket Runtime Doctor follows an observation-first methodology where systems are understood before engineering actions are taken.

---

# Getting Started

Launch Pocket Runtime Doctor.

The application opens to the main observation interface.

From this interface the user may:

• Admit a Patient

• Load a Patient

• Enter Observation Mode

• Review Reports

• Export Findings

---

# Standard Workflow

Launch Application

↓

Admit or Load Patient

↓

Observe System

↓

Run Taste Engine

↓

Review Results

↓

Generate Report

↓

Export Findings

↓

Discharge Patient

↓

Exit

---

# Patient Management

Patient represents the software system currently under observation.

Functions include:

• Admit Patient

• Load Existing Patient

• View Active Patient

• Discharge Patient

---

# Observation Mode

Observation Mode allows the user to inspect the current patient without modifying the system.

Information may include:

• Runtime State

• Telemetry

• History

• Reports

• Patient Status

---

# Taste Engine

The Taste Engine evaluates engineering quality.

Measurements include:

• Overall Health

• Structure

• Risk

• Maintainability

• Engineering Verdict

---

# Reports

Engineering reports summarize observations and findings.

Reports may be reviewed before export.

---

# Export

Current exports include:

• Text Reports

Future releases may support:

• JSON

• PDF

• AI Prompt Packets

---

# Engineering Philosophy

Observe before modification.

Verify before execution.

Document verified findings.

Expand only after successful verification.
