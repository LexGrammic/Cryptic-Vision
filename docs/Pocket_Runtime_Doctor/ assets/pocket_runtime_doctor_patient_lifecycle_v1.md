# Purpose

This document defines the complete lifecycle of a patient within Pocket Runtime Doctor.

A **patient** represents the software system currently under observation.

In traditional engineering terminology, the patient is the **analysis target**, **runtime target**, or **inspection target**.

This document is the engineering specification for:

**pocket_runtime_doctor_patient_lifecycle_v1.png**

---

# Objective

Provide a governed, repeatable lifecycle for every software system analyzed by Pocket Runtime Doctor.

Each stage produces observable engineering evidence before progressing to the next stage.

# Lifecycle

## Stage 1 — Admission

Engineering Term

Target Registration

Purpose

Register the software system for observation.

Outputs

• Patient ID

• Initial Status

• Observation Record

---

## Stage 2 — Observation

Engineering Term

Data Collection

Purpose

Collect runtime information without modifying the target.

Examples

• Runtime State

• File Structure

• Telemetry

• History

• Metadata

---

## Stage 3 — Analysis

Engineering Term

Engineering Analysis

Purpose

Evaluate engineering quality using the Taste Engine.

Measurements include:

• Structure

• Risk

• Maintainability

• Overall Health

---

## Stage 4 — Diagnosis

Engineering Term

Engineering Assessment

Purpose

Convert collected observations into verified engineering findings.

Outputs

• Engineering Verdict

• Weak Points

• Recommendations

• Health Status

---

## Stage 5 — Report Generation

Engineering Term

Report Construction

Purpose

Generate human-readable engineering documentation.

Outputs

• Doctor Report

• Summary

• Findings

• Engineering Notes

---

## Stage 6 — Export

Engineering Term

Artifact Generation

Purpose

Produce reusable engineering artifacts.

Current exports include:

• TXT

Future support includes:

• JSON

• PDF

• AI Prompt Packets

---

## Stage 7 — Discharge

Engineering Term

Target Release

Purpose

Complete the observation cycle and close the active patient session.

Outputs

• Final Patient Status

• Stored History

• Exported Reports

---

# Engineering Principles

Patient state is explicit.

Observation precedes analysis.

Analysis precedes reporting.

Reporting precedes expansion.

Every lifecycle stage leaves observable evidence.
